# リカバリーレコード仕様（1.2.0で実装）

## 使い方

通常の圧縮では復旧データを作りません。必要な書庫に対して明示的に作成する、外部ファイル方式です。FST・フォルダーFST・暗号化FST・ZIPに対応します。

GUIでは完成した書庫を選び「復旧データ作成」を押します。同じ場所に `書庫名.par` ができます。修復するときは破損した書庫を選んで「修復（.parが必要）」を押します。`.par` は元の書庫名に合わせて同じ場所に置きます。暗号化書庫ではパスワード欄に入力してください。出力は `書庫名.repaired.fst` 等の別ファイルです。

CLI:

```powershell
# 追加容量だけを確認（書き込みなし）
fastener recovery-create data.fst --estimate
# 完成した書庫から復旧データを作る
fastener recovery-create data.fst
# data.fst.par を使い data.repaired.fst に修復
fastener repair data.fst
# 別の場所の復旧ファイルを指定する場合
fastener repair damaged.fst --recovery backup/data.fst.par -o restored.fst
# 暗号化書庫は対話入力、または保護したパスワードファイルを使う
fastener repair encrypted.fst --password-file secret.txt
```

既存出力はCLIでは `--force` を付けない限り拒否、GUIでは確認します。修復先として破損した入力書庫や復旧ファイル自身を指定することはできません。受け手に渡す場合は書庫と `.par` の両方が必要です。復旧機能にはFastener 1.2.0以降が必要ですが、書庫本体の形式は変えていません。

## 訂正能力と容量

[reed-solomon-erasure 6.0.0](https://docs.rs/reed-solomon-erasure/6.0.0/reed_solomon_erasure/) のGF(2^8) Reed–Solomon符号を使用します。符号アルゴリズムの独自実装はしていません。

- 1グループはデータ20片＋復旧2片。
- 片のサイズは `ceil(書庫サイズ / 20)` を4 KiB〜1 MiBに収め、次の2のべき乗に切り上げます。
- 大容量では1 MiB片を使い、約10%の復旧データにヘッダー・索引分が加わります。
- 各グループで失ったデータ片と復旧片の合計が2個以内なら復元できます。データがすべて正常なら復旧片が両方壊れていてもデータの再構成は不要です。
- 破損位置は片ごとのBLAKE3で検出します。1バイトだけの破損でも、その片1個を消失として扱います。
- 最終グループの不足分は既知のゼロで補います。元の長さを保持し、出力にパディングを含めません。

追加容量は正確に `256 + グループ数 × (1488 + 2 × 片サイズ)` バイトです。最小構成でも9,936バイトを使うため、小さい書庫では10%を大きく超えます。端数がある大容量書庫でも10%を超えます。`--estimate` またはGUIの作成中表示で追加容量を確認できます。

**「任意の10%の破損が必ず直る」機能ではありません。** 同じグループの3片以上に被害が集中すると、数バイトの破損でも限界を超えます。索引は各グループの前後に2コピー、全体ヘッダーはファイル先頭と末尾に2コピー保存します。片側が壊れてももう片側を使用できますが、両方とも壊れると修復できません。正常なチェックサムを持つ2コピーが矛盾する場合も拒否します。

## 暗号化と安全な出力

順序は **圧縮 → 暗号化 → 完成した書庫から復旧データを作成** です。暗号化書庫の `.par` は暗号文から生成し、平文のファイル名や内容を格納しません。元書庫のバイト数・形式・暗号文のハッシュは保存します。復旧ファイル作成にはパスワードは不要です。

修復は別の一時ファイルで行い、復元した全片のハッシュ、元の長さ、書庫全体のBLAKE3を確認します。その後、通常のFST・フォルダーFST・ZIP検証、暗号化書庫なら全レコードの認証と内容ハッシュ検証を実行し、すべて成功したときだけ出力を確定します。暗号化書庫の修復には正しいパスワードが必須です。パスワードを忘れた場合の救済機能ではありません。

通常のハッシュは `.par` の作成者の正当性を証明しません。信頼できる場所に保存した復旧データを使用してください。また、作成処理は書庫のスナップショットを符号化するもので、元書庫が正常であることを保証しません。必要なら先に `fastener verify` で確認してください。破損した書庫から `.par` を後作りしても、以前の正常な内容は取り戻せません。

## 対応する破損と制限

対応するのは、バイト位置が保たれたビット反転・上書き・ゼロ埋めと、許容量内の末尾切り詰めです。途中のバイトが削除・挿入されて後続の位置がずれる場合の再同期は実装していません。許容量を超える場合は失敗とし、正常な出力に見せません。末尾に余分なバイトが追加された入力は、保存した元の長さに戻します。

OSが読み出せない物理セクターの救出ツールではありません。書庫全体の紛失など、残るデータと復旧片だけでは情報が足りない場合は復元できません。別媒体のバックアップも必要です。作成・修復中は入力を別のプロセスから変更しないでください。

復旧符号処理は1グループずつ行い、主要な片バッファは最大22 MiB、書き込みバッファは1 MiBです。これはプロセス全体のメモリ上限ではなく、最後の書庫検証やライブラリ内部のメモリは別です。最大グループ数は1,000,000。修復先ディスクには書庫全体のサイズの一時領域が必要です。通常の失敗・例外では一時ファイルを削除し、既存出力を保持します。強制終了や電源断での一時ファイル残留・永続化までは保証しません。
