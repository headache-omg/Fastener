# 圧縮・展開の仕組み

[English](../en/architecture.md) · [README](../../README.ja.md)

- **分割位置の決定。** 4 KiBのブロックから採ったサンプルの変化を採点し、目標サイズの近くで境界を選びます。ファイルは64 MiBの区間ごとに分析し、区間が目標の2倍以下なら採点を省きます。採点が必要で入力が16 MiB以上の場合は、CPUとwgpuで処理を分担できます。GPUが使えなければCPUに切り替わります。
- **圧縮。** Rayonが独立したチャンクをLZ4またはZstandardで並列処理します。圧縮で小さくならないチャンクは元のバイト列を格納します。GPUの処理は境界分析までで、展開はCPUだけで行えます。
- **大容量ファイル。** 通常のファイル処理はメモリマップを使い、チャンク数と256 MiBのデータ量を目安にバッチを制限します。メモリマップされたページやコーデックの作業領域、管理情報にもメモリを使います。展開時は、一時ファイルの重ならない範囲に並列で書き込み、ファイル順にバッチをハッシュします。チャンクとファイル全体のBLAKE3が一致してから出力を確定します。
- **フォルダーとZIP。** 通常のフォルダーFSTは各ファイルを独立したFSTとして収録し、空フォルダーを保持します。シンボリックリンクは収録から外します。フォルダーFSTとZIPは一時フォルダーに展開し、検証完了後に出力先へ移します。
- **暗号化書庫。** レコード単位の認証と、復元するファイル全体の検証を行います。検証だけなら平文ファイルの書き込みは不要です。展開時は一時領域に平文を書き、検証が完了してから出力を確定します。[暗号化形式](encryption.md)
