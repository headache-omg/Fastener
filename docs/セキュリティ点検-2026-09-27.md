# セキュリティ点検（2026-09-27）

この文書はFastenerの実装者側によるコード点検です。第三者による独立監査や、
未知の脆弱性がないことの保証ではありません。

## 対象と方法

- `FSTENC01` の鍵導出、nonce、AAD、レコード順序、マニフェスト、展開、失敗時の出力を確認。
- `FASTENR1`、`FASTDIR1`、ZIP、リカバリーの入力上限と公開前検証の経路を確認。
- `Cargo.lock` の crates.io 依存214件をOSVの `querybatch` に照合。
- Windowsで `cargo test --no-default-features`、`cargo test --all-features`、
  `cargo clippy --all-features --all-targets -- -D warnings` を実行。

## 是正した問題

暗号化書庫ではマニフェストの展開後合計サイズを認証していたものの、受け入れる
サイズに既定の上限がありませんでした。パスワードを知る送り手が、高圧縮率の
データを含む書庫を作ると、受け手の空き容量を大量に消費できました。

復号・検証・修復時の既定上限を64 GiBに設定しました。認証済みマニフェストの
サイズを、平文の一時出力を作る前に検査します。信頼できる大容量書庫に限り
`--encrypted-max-output-bytes BYTES` で上限を明示的に引き上げられます。
ライブラリ利用者は `EncryptedLimits` を指定できます。

## 依存クレートの照合結果

- [`RUSTSEC-2024-0384`](https://rustsec.org/advisories/RUSTSEC-2024-0384.html):
  `instant 0.1.13` は保守終了の通知です。現時点で特定の脆弱性を示す通知では
  ありません。`reed-solomon-erasure 6.0.0` → `parking_lot 0.11.2` の間接依存です。
- [`RUSTSEC-2026-0253`](https://rustsec.org/advisories/RUSTSEC-2026-0253.html):
  `lru 0.7.8` の `LruCache::pop()` で、キーの `Drop` がパニックするときの
  use-after-free です。間接依存の `reed-solomon-erasure 6.0.0` は
  `LruCache<Vec<usize>, Arc<Matrix<_>>>` を使用し、参照箇所は `get` と `put` です。
  キー `Vec<usize>` の `Drop` はパニックせず、この報告の発生条件には該当しません。
  依存先やキー型を変える場合は再評価が必要です。

今回の照合で上記以外のOSV報告は見つかりませんでした。ただし、アドバイザリの
未登録、条件付きの影響、将来の新規報告はこの結果から否定できません。

## 残る限界

- パスワードを知る相手は正しく認証される書庫を作れます。暗号化は送り手の身元を
  証明しません。上限を明示的に引き上げた場合、その容量消費を許可することになります。
- 平文の一時出力は同じ親ディレクトリに作成します。強制終了や電源断後の残存、
  SSD上の安全な消去、スワップやメモリダンプへの耐性は保証しません。
- ファイルシステム上の別プロセスが、入力や出力先を処理中に差し替える状況は
  今回の攻撃モデルに含めていません。
- 独立した第三者監査と継続的なファジングは別途必要です。
